# 微光群岛：实施边界与引擎决策

2026-10-04 更新：按用户决定，当前项目不采用 Unity，也不继续比较 Unity。当前MVP优先普通微信小程序，用于验证运动识别路径；正式发布类型和展示引擎仍按实际能力确认。

目标是微信优先的轻量运动游戏，清爽扁平风格，面向小范围成人试用。Cocos Creator + TypeScript 是游戏展示层优先候选；其摄像头、姿态模型和微信目标运行时必须先经过真机验证。普通微信小程序与微信小游戏是不同运行环境，不能把普通小程序 camera 组件的结果直接认定为小游戏能力。

v0.4交付规则模块、普通小程序界面与实验识别适配器，不是已确定的最终 Cocos 工程，也不是完整运动识别产品。

## 模块边界

- `src/core.ts`：纯规则；固定关卡、回合、来源、技能、暂停、事件去重。渲染器不能自行修改血量。
- `src/storage.ts`：本地双槽快照、校验与版本拒绝；保存成功后发布状态，失败则阻止后续输入并允许重试。
- `src/ui.ts`：真实规则状态到五种界面的映射、轮次统计和保存成功后的反馈差值。
- `preview/`：浏览器按钮样机；清爽扁平视觉和交互，不用于证明微信性能。
- `miniprogram/`：普通小程序按钮/摄像头适配器及实验模型运行入口；复用编译后的同一规则模块。
- 后续 Cocos 适配器：消费状态，提交规范动作事件；不复制关卡算法。
- `src/recognition.ts`：关键点坐标还原、实验俯卧撑周期计数与异步推理帧泵。
- `miniprogram/recognition`：可选TFJS3.x插件与MoveNet GraphModel适配，默认关闭，未经微信真机推理验证。
- 运动链路：摄像头 → 模型 → 各动作档案状态机 → 合格动作事件。事件携带轮次、输入 epoch、来源、档案和唯一 ID。

当前档案名称仅用于来源隔离；没有任何档案通过真实运动识别验证。按钮记录不计入将来的摄像头成绩或多人排名。

## 首关 v1

三个阶段：40；30+30；80。总护盾180。每次合格事件基本伤害10；累计每4次得到1份能量，最多2份。聚光额外10；散光对两存活目标各5，单目标10。先结算基本伤害，基本攻击击破目标时保留预选技能；伤害不溢出至其他目标或下一阶段。阶段切换须明确确认，运动输入暂停。简单模式无死亡、无强制时间压力。

每轮保留动作数、实际贡献、来源和档案；退出可跨轮继续。当前存储只在本设备，尚无账号或云同步。记录具有 schemaVersion、rulesVersion、levelVersion；未知版本保留原数据并拒绝覆盖。暂未实现版本迁移、跨设备同步、多关卡注册表和服务端防作弊。

本地快照校验用于意外损坏检测，不是签名或反作弊。双槽只能退回一个有效旧快照，不能承诺操作系统崩溃时零丢失；不主动清空损坏存档。

## 下一步真机门槛

1. 确认普通小程序AppID与后台插件可用性；AppID用于开发配置，不需要AppSecret，密钥和身份信息不得写进公开仓库。
2. 在 Windows 微信开发者工具导入平台探针，完成隐私声明及摄像头调用要求，真机预览 Xiaomi14。
3. 检查权限拒绝、取帧分辨率、帧率、前后台恢复和相机停止。当前仅输出宽高、字节数、帧数与耗时，不保存图像。
4. 验证候选MoveNet Lightning与TFJS插件能否在实际微信运行时执行，并测加载时间、推理延迟、内存、渲染并行、温升。分别测靠墙与地面俯卧撑，未通过的档案禁用。
5. 在 Cocos 微信目标工程中复现相同链路，比较结果后固定展示层方案。若小游戏摄像头受限，应重新评估普通小程序内 Canvas/WebGL 展示路径。
6. 运动计数与交互已有实验实现，仅在上述实测门槛通过后开放小范围摄像头体验；多人 PK 留待公平性、同步和服务端验证完成。
