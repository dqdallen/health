# 微光群岛 · 角色与场景制作方案

## MVP决定

保留炉心守卫作为关卡互动角色；玩家通过动作注入微光，没有必要额外加入可移动的玩家角色。场景是浮岛、守卫、灯笼和光效的2D分层组合。不做3D建模，不增加自由移动、碰撞、寻路或复杂战斗AI。这是适应俯卧撑节奏的制作选择，不是说运动游戏不能使用这些系统。

现有素材是透明PNG，现有scene-layout.svg可调整三大元素的位置；它不是守卫内部可编辑的PSD或骨骼文件。当前整体位移和发光反馈可由代码实现，手臂关节动作不能从一张PNG直接获得完整制作源文件。

## 分阶段资产

| 阶段 | 角色 | 场景 | 动画与产物 |
|---|---|---|---|
| 当前识别MVP | 现有炉心守卫PNG、灯笼 | 现有浮岛PNG与背景色 | 漂浮、短促受击、数字贡献、阶段点亮；已有代码 |
| 首轮识别实测之后 | 同一守卫分层绘制头、躯干、上臂、前臂、腿和灯芯，补全遮挡区 | 前中后景、光层可独立控制 | 待机、回应、受击、恢复、点亮；分层源文件、透明PNG与图集 |
| 确实需要复杂动作时 | 为分层角色建立2D骨骼 | 沿用2D场景 | 选择Spine导出骨骼与图集，并配置实际渲染器兼容版本 |

不要将AI生成整张海报作为可交互UI，也不要只把现有整图切成肢体而遗漏遮挡处。按钮、数字、计数、进度、错误和状态仍用原生UI与真实状态驱动。

## 平台与职责

- **现在必须**：Windows微信开发者工具（导入、构建npm、调试、手机预览），Node.js（构建和测试），微信小程序后台（AppID、插件、隐私与模型域名）。
- **识别模型文件托管**：只有没有现成HTTPS托管时才新增云服务；腾讯云COS可作为候选。画面不上云，不是购买识别API。
- **UI编辑可选**：已有Figma连接可用于后续可编辑组件和页面；不需要为这次识别再装ChatGPT插件。
- **2D绘画可选**：Krita或Photoshop等制作分层源图；只有进入分层角色制作阶段才需要。现有PNG可以先用。
- **Spine可选**：有复杂角色动作需求后再评估购买和运行时授权。官方说明角色由多张分层图片组成，先准备图再绑定骨骼；官方说明 https://esotericsoftware.com/spine-first-steps 。
- **Cocos待定**：需要统一图集、时间轴或骨骼渲染时做技术验证；现有项目仍是TypeScript核心+微信原生2D表现，不是已经移植到Cocos。Cocos支持Spine资产，但版本和目标运行环境必须匹配：https://docs.cocos.com/creator/3.8/manual/en/asset/spine.html 。
- **Higgsfield可选**：已连接，可用于辅助生成素材或宣传视频；不是小程序运行引擎、人体识别工具，也不会自动输出经过制作验收的分层骨骼资产。
- **Blender不需要**：当前没有3D角色或场景建模任务。

## 下一步顺序

先验证模型加载、相机方向、计数和发热 → 完成靠墙动作校准与免手触提示 → 再做分层角色动画 → 依据动画需求验证渲染器 → 增加地面档案和其他游戏模式。识别准确率和动作反馈验收前，不追加大量关卡美术。
