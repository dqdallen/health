# 俯卧撑识别接入 · 0.4.0 实验版

## 站姿抬腿实验入口

群岛入口选择「踏光栈道」。三个动作段依次为交替抬膝、交替侧抬腿、交替抬膝，保持同一正面机位，包含双肩、髋、膝、脚踝。每段完成立即停止相机计数，显示下一动作；确认继续后建立新动作轮次并重置识别状态，不拼接半次动作。记录按段保留具体动作、来源、次数和贡献，使用weiguang:knee-01存档前缀；原俯卧撑仍为weiguang。

复用MoveNet的髋、膝、踝关键点，不需要新的模型。实验初值：关键点置信度0.5、姿势连续3帧、抬起到放下至少600ms、丢帧超过1500ms或遮挡取消半次、抬起超过10秒重置。抬膝按膝相对髋的高度与躯干尺度判断；侧抬腿按髋踝外展角（抬起25°、回落12°）和膝角（150°）判断，同时过滤向内交叉腿。单侧脚离开基线并回落才计次，连续同侧动作提示换侧。

这些数值只用于实验过滤，不是训练或标准动作要求；尚未做真实抬腿校准。先人工对照少量自然动作，检查左右两侧、衣物遮挡、机位、暂停恢复、关卡动作切换；若需要刻意改变舒适动作才能被识别，应反馈调整识别阈值。当前不做动作质量评分。

## 实现与未验证的边界

代码链路：微信 camera RGBA 实时帧 → TFJS GraphModel（MoveNet SinglePose Lightning）→ 17个人体关键点 → 单侧肩/肘/腕角度和髋部可见性 → 稳定撑起、下降、撑起 → camera来源的游戏动作 → 持久化成功后播放攻击反馈。

已经完成计数模块、模型输入输出适配、摄像头轮次、保存与生命周期连接。自动测试使用合成关键点，不代表真实识别准确率。未在微信开发者工具或小米14运行真实模型，未验证个人主体后台是否提供所需插件、包体积是否满足目标发布条件、当前微信与 TFJS 插件的兼容性。默认关闭真实识别，配置失败时不会创建运动轮次。网页预览仍为按钮体验。

当前是动作周期实验计数器，不判断俯卧撑动作质量，也无法可靠区别所有相似的弯肘动作。不能用于医疗评估、排行榜反作弊或强度处方。地面档案只切换躯干方向过滤规则，尚未完成独立真机验证。

## Windows 准备与启用

1. 安装 Node.js（项目要求 >=22）和微信开发者工具。根目录执行 `npm ci`、`npm test`。
2. 微信后台提供普通小程序 AppID。在“设置—第三方服务—插件管理”搜索官方文档的 TFJS 插件 provider `wx6afed118d9e81df9`，确认你的主体能添加以及后台可用版本。README记录0.2.0支持TFJS3.x；版本较旧，必须做兼容验证，不保证现网可用。插件不是ChatGPT插件。
3. 准备 MoveNet SinglePose Lightning v4 的 **TFJS GraphModel**（不是TFLite或SavedModel）：`model.json` 和其中 `weightsManifest` 引用的全部权重文件。来源和许可随下载保存。不能把其他模型的json冒充此模型。没有重新训练和付费识别API的要求。
4. 将模型文件放到你控制的 HTTPS 静态托管上，并保持相对路径。可先用已有托管；如没有，再配置腾讯云COS等。是否需要备案、域名和部署地区以实际微信后台及服务商要求为准。将所有模型请求域名加入微信后台合法域名；模型下载可能触发重定向，应避免未配置的域名。小程序不发送摄像头画面，只请求模型文件。
5. 根目录运行：
   ```sh
   npm run configure:recognition -- --appid wx你的AppID --model https://你的域名/movenet/model.json --plugin-version 后台可用版本
   cd miniprogram
   npm ci
   ```
   根目录 `npm ci` 不安装摄像头推理依赖。小程序目录另有独立锁文件：TFJS core/converter/backend-webgl 固定3.21.0，fetch-wechat0.0.3。这是依据3.x文档选择的兼容候选，未经过手机验证。
6. 开发者工具导入根目录，用普通小程序方式打开，执行“工具—构建npm”。配置实际隐私保护指引与摄像头使用说明；首次测试需要微信的摄像头许可。此版本未自定义隐私同意弹窗，按后台和基础库实际要求补齐后再分享测试。
7. 小米14真机预览，选择靠墙档案，点“摄像头俯卧撑·实验功能”。模型加载失败会给出错误，按钮体验仍然独立可用。

AppID可提供给开发者；不需要AppSecret、微信密码或新GitHub token。默认工程是游客AppID，不能据此验收插件或真机识别。

## 摆放与第一次测试

先测试靠墙俯卧撑。手机稳定支撑在身体侧面，画面包含肩、肘、手腕、髋部；单人、光线充足，先稳定撑起。实际距离与横竖屏以小米14取帧方向调试结果确定。不要为了凑识别角度强行改变动作或额外增加训练量。

当前阈值是实验初值：关键点置信度>=0.5；撑起肘角>=155°、下降<=110°；连续3帧确认；周期>=600ms；丢帧间隔>1500ms或低置信度重置未完成周期；周期>10s重新等待完整动作。暂停和恢复要求重新开始一个完整周期，半个动作不拼接计数。不同人的活动范围不同，下一步依据实测增加个体校准，而不是把这些阈值称为标准动作要求。

帧处理最多一个推理进行中，忙时丢帧；原生入口最多每100ms提交一帧。不保证10FPS。禁止混合按钮与识别输入。到阶段结束、暂停、切后台、关闭摄像头时停止取帧，过期推理结果不能攻击。模型保留到页面卸载；卸载后等待在途推理释放张量再销毁模型。每次推理释放输入与输出张量。

## 验收记录（待用户真机测试）

| 场景 | 要验证的结果 |
|---|---|
| 静止撑起或中间姿势 | 不重复计数 |
| 正常完整动作与小幅弯肘 | 完整动作计数，小幅动作不计；人工对照 |
| 暂停在下降中，再恢复 | 旧半次不计 |
| 离开画面、遮挡、左右手切换 | 不拼接出误计数 |
| 阶段结束后继续运动 | 未点下一阶段不扣血 |
| 关闭摄像头、切后台、重进 | 保留进度，无迟到攻击 |
| 网络中断或模型加载失败 | 明确报错，无伪造计数 |
| 保存失败 | 停止计数，无未保存攻击反馈 |
| 连续运行与温度 | 记录首次加载、推理耗时、掉帧和发热 |

人工计数与识别计数分开记录；先收集少量自然动作，再决定阈值、模型或后端。未验收前不启用多人PK、排名与运动奖励兑换。诊断只复制帧数/尺寸/时间/模式，不含画面或关键点日志。
