# 微光群岛 · 炉心守卫

站姿关卡增量：群岛入口新增「踏光栈道」，在同一个游戏内依次完成交替抬膝、交替侧抬腿、交替抬膝。全程正对镜头、双脚入镜，过段暂停并提示下一动作，用户确认后继续。按钮模式可先体验完整流程；MoveNet 实验识别复用已有模型，不需下载新模型，但动作阈值尚未经过真实抬腿校准。新关卡使用独立本地存档，原炉心守卫记录继续使用原键名。

v0.4：在现有五态2D关卡上加入实验性俯卧撑识别链路：摄像头帧、MoveNet关键点适配、周期计数和真实游戏攻击。按钮体验继续可用，两种来源分轮记录。**识别代码已接入，真实模型与小米14识别效果尚未验收；默认关闭，需要AppID、微信插件和模型托管配置。**

计数测试使用合成关键点，不代表手机准确率。网页预览仍为按钮版本。完整启用步骤见 [识别接入与真机验收](docs/recognition.md)，角色、场景与平台选择见 [美术制作方案](docs/art-production.md)。当前仍是TypeScript核心+微信原生2D界面，没有Unity或Cocos引擎接入。已有美术和浏览器五态截图见design。

## Windows 准备与本地体验

从 Git 克隆项目后，先将 `miniprogram/recognition/config.example.js` 复制为同目录的 `config.js`。本地识别配置包含短期签名链接，不提交 Git；依赖、微信 npm 构建产物和下载的模型也不提交。已有本地 `config.js` 时保留它。

安装 Node.js 22或更新版本、Git、微信开发者工具。解压源码后在项目目录运行：

```powershell
npm ci
npm test
npm run preview
```

浏览器打开 http://127.0.0.1:4173 。点击“开始这一轮”后，用按钮模拟动作。每4次获得技能，选择聚光或散光；过阶段后点击进入下一阶段。可以休息、结束本轮、重新打开继续。按钮模拟数据会明确标记来源。

网页点击左上角星标返回群岛，选择「踏光栈道」。微信启动时显示两座岛；也可点击左上角「微光群岛」返回选岛。新关卡三段微光目标为60、40+40、80，总计220；无技能时分别模拟6、8、8次动作完成。每次完整抬起并放下计1次，左右交替，每个动作段自动记录为独立轮次。相机识别仍需有效模型链接、平台配置和真机验收。

## 微信预览

1. 先运行 `npm run build`，生成 `miniprogram/lib`（产物不提交仓库）。
2. 在 `miniprogram` 目录运行 `npm ci`，用微信开发者工具构建npm；推理依赖独立安装。用微信开发者工具导入**项目根目录**。项目配置已指向 `miniprogram/`，编译类型为普通小程序。
3. 将示例 `touristappid` 换成自己的普通小程序 AppID。游客模式能否预览或真机调试以工具当前能力为准；相机真机测试需要实际账号配置。
4. 根据微信后台要求配置隐私声明和摄像头用途。相机只在用户主动启动诊断或识别时打开；不需要为按钮体验开启相机。
5. 在 Xiaomi14 上预览。先测试按钮记录，再按 docs/recognition.md 配置模型后测试相机。若 AppID 是小游戏账号，停止此导入路径，反馈给开发者以切换平台工程。

微信开发者工具与真实手机尚未在此环境执行，WXML/WXSS 和取帧入口待验证。VM适配器测试验证按钮和合成姿态输入、保存及生命周期处理；不模拟真实wx运行环境。

## 请反馈的结果

- AppID **类型**：普通小程序 / 小游戏；实际 ID 可后续提供，不要提交密钥。
- 按钮测试：打4次、结束一轮、关闭再打开，贡献应40，轮次动作应4；继续第二轮后进入阶段2。
- 前后台：运动中切后台再回来应暂停，不额外增加次数。
- 相机诊断：允许或拒绝权限后页面表现；允许时复制诊断结果（宽高、帧数、字节数、耗时）。不要发送原始相机画面。
- 帧诊断不代表识别成功；模型加载、准确率、延迟、内存与发热需要真机实测。

## 验证

`npm test` 编译两种模块格式，执行纯规则、存档与微信适配器测试。浏览器检查脚本 `tests/browser.mjs` 需要安装 Playwright 及 Chromium，详见 [验证状态](docs/validation.md)，可执行 `npm run test:browser -- --serve`。

当前存档仅在设备本地；无云同步、用户登录、多关卡、多人生效成绩或排行榜。重新开始与记录导出将另行设计，避免误清空已有进度。
